# v0.1.0 实现说明

原始 PRD 保留在 `PRD.md`，其中的规划清单没有改写。当前实现覆盖 F01–F09：项目识别、成功 `nvm use` 自动记录、JSON 存储、目录变化恢复、启动恢复、相同版本跳过，以及 list/forget。

## 关键实现

- CLI：CommonJS + Node 标准库，运行时兼容 Node.js 14.20，无第三方依赖。
- 项目：真实绝对路径，向上查找最近的 package.json。
- 存储：schema 校验；写入前 mkdir 锁、重新读取、0600 临时文件、fsync、rename；损坏文件禁止覆盖；读操作不创建空配置。
- Shell：复制 nvm 函数，转发原始参数并保留退出码；动态作用域标记阻止嵌套调用记录；初始化一次并注册 chpwd。
- CLI 与版本切换：由当前 Shell 调用原 nvm，子进程只读写配置。固定 CLI 和 Node 路径，保证 nvm 更改 PATH 后仍可调用。
- 初始化：交互确认或显式 --yes，备份原配置，替换自身区块，支持 ZDOTDIR 和软链接 dotfiles。

## 与需求规划的补充

1. 对并发写入增加进程锁，防止两个终端互相覆盖项目记录。
2. 配置缺失时读取为空，首次保存才创建 JSON，避免无记录项目触发写入。
3. 增加 list --json、--version、显式版本保存和配置目录覆盖环境变量。
4. 固定的 CLI 运行时可能与当前终端版本不同，因此自动记录和 Hook 提供的普通 save 均读取 nvm current，并传递完整版本；未加载 Hook 的 CLI save 使用运行 CLI 的版本。
5. 包名采用 @lspdesign/node-memory，CLI 仍为 node-memory。

## 已验证场景

单元和 Shell 集成测试覆盖子目录、软链接、空格路径、Monorepo 子包、无项目/无记录、版本相同、版本缺失、损坏配置、并发保存、锁超时、命令退出码、重复加载、缺失运行时、配置备份与幂等。

真实 zsh + nvm 测试验证已安装版本之间的手动记录、cd 往返恢复、新 Shell 启动恢复、失败不覆盖、离开项目保留版本、不同 Shell 环境独立。

所有功能测试在临时目录执行，真实 nvm 测试只修改其子 Shell 的环境。测试不安装 Node，不修改个人终端配置或个人版本记录。

## 已知边界

首发仅支持 macOS + zsh + nvm；不自动安装版本，不恢复离开项目后的默认版本，不调整已有进程，不对 Monorepo workspace 做合并识别。卸载 Hook 捕获的 Node 运行时之后需要重新初始化。异常退出残留的写锁需按 README 手动清理。
